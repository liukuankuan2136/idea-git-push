IDEA 插件设计方案

目标是在本机 IntelliJ IDEA Ultimate 2026.1.4 上提供与 VS Code 版业务能力等价的插件，并把串行 QuickPick/InputBox 改为“一项业务、一个主弹窗”。

目录 1. 目标与原则 2. 版本支持 3. 功能设计 4. 入口与使用方式 5. 单弹窗 UI 6. 技术架构 7. 工程结构 8. DevOps 接入 9. Git 与事务 10. 配置与存储 11. 异步与状态 12. 安全与日志 13. 错误与恢复 14. 构建安装 15. 升级与回滚 16. 测试验收 17. 实施阶段 18. 官方依据

1. 目标与设计原则

目标

  • 完整覆盖 VS Code 0.3.12 的核心业务功能，而非只迁移 Git 提交部分。
  • 在本机 IntelliJ IDEA Ultimate 2026.1.4 可稳定安装、运行和升级。
  • 把同一业务流程的选择、输入、预览、执行和结果合并进一个主弹窗。
  • 保留现有 DevOps 协议、commit 格式、工时模式、任务模板和区域检查规则。
  • 明确跨 Git/DevOps 操作的部分成功状态，并提供可操作的恢复提示。

非目标

  • 不兼容 VS Code 扩展包或复用其 UI 代码。
  • 首期不承诺 IntelliJ IDEA 2025.x、2026.2+、Android Studio 或其他 JetBrains IDE。
  • 首期不发布 JetBrains Marketplace；以本地 ZIP / 公司私有仓库为主。
  • 不改变公司 DevOps 后端，也不引入 AI 服务。
核心 UX 约束。一个用户动作最多出现一个业务主弹窗。字段级确认、项目切换、手动任务编号、commit 预览、执行进度和结果都在该弹窗内完成；只有系统级文件选择器或不可避免的 IDEA 安全提示不受此限制。

功能保留清单

  • Task/Bug 切换、按产品分组、标题/编号搜索、跨人员手动编号查询。
  • commit 类型、subject 校验、模板实时预览、复制提交信息。
  • 工时类型、AI 工时参数、工时/描述/进度追加或覆盖。
  • 首次 push 的 remote/branch/set-upstream 处理。
  • 仓库与项目/产品记忆、工作区与项目/产品记忆；重新选择后更新映射。
  • 产品版本、区域自动识别、实施项目级联、未完成任务预计结束日期。
  • 简易/普通/标杆任务模板和工时类型→任务类型映射。
  • 今日工时、明日计划、工时不足 8h 提示、逾期任务提醒和日报提交。
  • 中国省市静态匹配、区域规则 A、实施项目规则 B。

已确认的行为选择

  • 运维补录工时类型：按弹窗中用户实际选择的工时类型登记，不再强制改为“代码编写”。
  • 简易任务模板：保持 VS Code 现状；未在简易/普通模式中展示的章节，仍按现有模板逻辑写入默认指导文案。

4. 入口与使用方式

菜单入口

在 Tools → Issue Link Push 注册统一 Action Group，包含全部 9 个动作。所有 Action 同时可通过 Find Action 搜索，快捷键由用户在 IDEA Keymap 中自行绑定。

首次使用

  1. 安装插件 ZIP 并重启 IDEA（如 IDEA 要求）。
  2. 打开 Settings → Tools → Issue Link Push。
  3. 填写 DevOps 用户名和登录 password 密文，点击“Apply”或“OK”保存。
  4. 在项目中执行 Tools → Issue Link Push → 关联 DevOps 任务提交并推送。

日常提交

  1. 先在 IDEA Commit 工具窗口暂存需要提交的改动；若选择“重写并推送”，则准备好一个未推送 commit。
  2. 打开“关联 DevOps 工作项”弹窗，在同一页完成任务、提交信息、工时和完成度。
  3. 核对底部实时 commit 预览，点击与模式对应的主按钮。
  4. 弹窗内显示每步结果；全部成功后可直接关闭，失败时按提供的恢复动作处理。

无 Git 的任务登记

执行“创建日常任务”，选择/确认项目产品、区域、工时类型与任务内容后直接创建 Task 并登记工时。该功能只要求 IDEA 已打开项目，不要求项目启用 Git。

5. 单弹窗 UI 设计

实现基础为 IDEA DialogWrapper + 平台 Swing 组件。弹窗支持 Esc、平台按钮顺序和字段级 ValidationInfo；级联数据在后台加载，不关闭弹窗、不再弹第二个选择框。

5.3 日常任务弹窗

复用创建任务表单，隐藏 Git/Commit 区域，主按钮改为“创建任务并登记工时”。项目产品基于当前 IDEA Project 记忆。

5.4 日报弹窗

加载、编辑、警告和确认都在一个弹窗内。用户点击主按钮即提交，不再额外出现“最终确认”消息框。

5.5 区域合规检查弹窗

顶部为研发项目、产品和“开始检查”（首期范围固定本周）。运行后在同一弹窗下半部生成文本报告，包含任务编号、标题、处理人、区域、实施项目、命中地名和结论；可直接全选复制，不打开通用日志窗口。

5.6 设置页

Settings → Tools → Issue Link Push 集中配置账号、提交与工时、任务创建、网络与缓存、诊断。账号通过 Apply/OK 保存；“清除 DevOps 缓存”动作统一清理会话、字典缓存、版本记录和项目映射，但不删除 PasswordSafe 凭据。

6. 技术架构

Actions / Settings：入口、可用性判断、打开 DialogWrapper；Action 本身无业务字段，避免泄漏 Project。
Dialogs：DialogWrapper + IDEA Swing 组件、字段状态、异步级联、校验、预览、步骤结果。
Application Use Cases：LinkWorkItem、CreateOpsTask、CreateDailyTask、SubmitDailyReport、CheckRegionCompliance。
Domain：模型、commit 格式、工时策略、任务类型映射、模板渲染、区域规则、操作结果。
Ports：DevOpsGateway、GitGateway、CredentialStore、SettingsStore、MappingStore、Clock、Logger。
Infrastructure：CompanyDevOpsClient、Git4IdeaGateway、PasswordSafe、PersistentStateComponent、IDE Notifications。

关键设计决定

  • Kotlin/JVM 21；不嵌入浏览器 WebView，避免额外前端工程和 JCEF 复杂度。
  • UI 用平台原生组件，自动适配主题、缩放、键盘与无障碍。
  • 领域层不依赖 IntelliJ 类，以便纯 JVM 单元测试。
  • 所有外部写操作由 UseCase 编排并返回结构化步骤结果，不在 Dialog 中直接串 API。
  • 统一使用 Asia/Shanghai Clock，消除当前 UTC 日期边界问题。

8. DevOps 接入设计

客户端拆分

类职责
DevOpsSessionClient登录、Cookie/userId、登录失效重试一次、连接测试
WorkItemClientTask/Bug 列表、两阶段分组查询、按编号查询、本周产品任务；普通任务列表固定复刻 VS Code 的 groupId=6 / groupField=executeUser
WorkHourClient工时列表、类型、新增、修改
TaskCreationClient项目、产品、版本、区域、实施项目、字典、创建 Task
DailyReportClient今日工作、明日计划、工时校验、逾期检查、日报提交
DevOpsPayloadParser标准 JSON 与非标准 IIFE 兼容解析

已确认的协议边界

  • 普通 Task/Bug 列表以现有 VS Code 源码为唯一基线，固定使用 groupId=6、groupField=executeUser，不为 HAR 中网页端的 groupId=1 / createTime 增加抽象兼容。
  • 增量 HAR 中的 /devops-server/config/v3/task/modify/task 来自用户在详情页面点击“保存”；它不属于现有插件的工时登记职责，IDEA 版不实现、不调用。
  • HAR 仅作为真实 IIFE 响应及“详情 → 工时列表 → 新增工时 → 刷新”链路的增量证据；其他接口继续以已验证可用的 VS Code 适配器为迁移基线。

网络实现

  • 优先使用 JDK 21 HttpClient，显式连接/请求超时，统一 User-Agent。
  • 只允许 HTTPS 和固定主机 devops.ctjsoft.com；禁止自动跟随到其他主机。
  • Cookie 只在内存 Session 中保存，不写日志、不落普通配置文件。
  • 401/登录页响应触发一次重新登录并重放幂等查询；写请求不自动盲目重放，避免重复 Task/工时。
  • 对响应体设置上限；错误日志仅记录端点代号、状态码、requestId，不记录 Cookie、password、完整 user-context。

非标准 IIFE 响应

采用双通道解析：

  1. 先按标准 JSON 解析；这是绝大多数端点的快速、安全路径。
  2. 仅对已登记的兼容端点、固定 HTTPS 主机、符合特征的响应进入 Legacy Parser。
  3. Legacy Parser 首选基于真实样本实现受限结构转换；若样本证明必须执行 IIFE，则将 Rhino 作为独立依赖，关闭 Java 类访问，限制脚本时长、指令数和响应大小，再把结果转成普通 JSON Tree。
  4. 未知脚本结构直接失败并给出诊断，不执行任意扩展语法。
IIFE 样本门槛已满足。loadtask-savedaywork.har 已提供三份真实 IIFE 响应，可用于验证解析结构。实现前从原始 HAR 生成脱敏 fixture 并加入回归测试；原始 HAR 含内部任务与人员信息，不提交 Git。

9. Git 集成与事务设计

技术方案

使用 GitRepositoryManager 获取当前 IDEA Project 下的 Git roots；用 Git4Idea 的命令封装执行 git，以继承 IDEA 的 Git 可执行文件配置、认证环境和取消机制。底层命令语义保持与 VS Code 版一致：commit -m、commit --amend --only -m、push、push --set-upstream、reset --soft。

仓库选择

  • 单 Git root 自动选中；多 root 在主弹窗顶部组合框选择。
  • Action 的 update() 只做轻量判断；完整 Git 状态在后台加载。
  • “仅提交/提交并推送/运维补录”要求 staged changes；“重写并推送”要求至少一个未推送 commit。
  • 无 upstream 时在同一窗内出现 remote 与 branch 字段；默认当前分支。

执行计划与补偿

模式步骤补偿策略
重写并推送amend → push → 工时push 失败 soft reset 到执行前 HEAD/reflog；保留恢复命令供复制
提交并推送commit → push → 工时push 失败 soft reset 新 commit；恢复 staged changes
仅提交commit → 工时工时失败默认不回滚 commit，提供“重试登记工时”
运维任务建 Task → commit → push → 工时Task 不删除；push 失败继续工时；结果明确显示“部分成功”
日常任务建 Task → 工时工时失败保留 Task并提供任务链接与重试

每次执行前记录 beforeHead、仓库 root、分支和 staged 状态摘要。恢复只针对本次新产生的 commit 且必须验证 HEAD 仍符合预期；如果用户/外部进程已改变仓库，停止自动恢复并显示手工命令，避免误 reset。

缓存策略

  • 会话 Cookie：内存，插件/IDE 重启即失效。
  • 项目、区域、工时类型、字典：按 TTL 内存缓存。
  • Task/Bug 列表：默认实时请求；弹窗提供刷新按钮，不受通用 TTL 误导。
  • 产品、版本、实施项目：按父级 ID 在当前会话缓存，父级变化立即切换。
  • 清理动作分为“清运行缓存”“清项目映射”“删除 DevOps 账号”“清全部非凭据数据”。

模板变量校验

设置页实时检查 5 个必需变量，缺失时不允许 Apply；提供“恢复默认模板”和示例预览。账号保存时先后台测试连接，成功后再覆盖现有 PasswordSafe 值。

11. 异步、线程与弹窗状态

平台 2024.2+ 推荐协程执行上下文。设计使用项目/应用 Service 的 coroutine scope；网络、PasswordSafe 和 Git 操作不在 EDT 执行，UI 状态回到 EDT 更新。

状态UI 行为允许关闭
LOADING相关字段显示加载状态；其余字段可编辑是，取消子任务
EDITING完整编辑和实时校验是
RUNNING_READ检查/刷新可取消，显示进度是，触发取消
RUNNING_WRITE字段锁定，显示步骤清单；不再接受重复点击默认否，直至当前不可中断步骤结束
PARTIAL_SUCCESS显示成功/失败步骤、任务链接、重试或复制恢复命令是
SUCCESS显示完成摘要；主按钮变“关闭”是

级联请求使用版本号/Job 取消避免竞态：例如用户快速切换研发项目，旧产品请求即使较晚返回也不得覆盖新项目的产品列表。

12. 安全与诊断日志

  • password 密文仅进 PasswordSafe；Windows 默认由 IDEA 的 KeePass 形式凭据存储承载。
  • PasswordSafe 的 get/set 是阻塞调用，统一在 IO dispatcher 执行。
  • 不记录 password、Cookie、Set-Cookie、完整 Authorization/user-context 或完整登录响应。
  • 日志中的用户名、userId、任务内容默认脱敏；debug 模式允许端点与字段名，但仍不输出凭据。
  • 任务详情和日报属于公司内部数据，不上传第三方，不调用 AI。
  • Legacy IIFE Parser 只接受固定主机/端点响应并启用执行限制；普通文本绝不进入脚本执行。
  • 插件 ZIP 若在公司范围分发，建议使用证书签名并记录 SHA-256。

日志位置与用户入口

普通结果在弹窗内；诊断写 IDEA 日志并使用统一 logger category。设置页提供“打开日志目录”“复制脱敏诊断信息”，不额外常驻一个工具窗口。

13. 错误模型与恢复

错误类型用户提示动作
AUTH账号失效或登录失败打开设置 / 重试连接
NETWORK超时、DNS、HTTP 状态和端点代号重试当前读取；写请求先查询结果再决定
PARSEDevOps 响应格式变化复制脱敏诊断；保留响应摘要哈希
VALIDATION字段旁显示原因聚焦第一个错误字段
GIT_PRECONDITION无 staged、无未推送 commit、无 remote给出明确准备步骤
GIT_COMMAND显示 Git 原始 stderr（过滤凭据 URL）自动恢复或复制恢复命令
PARTIAL_SUCCESS逐步显示哪些已完成、哪些失败重试工时 / 打开 Task / 手动 push

写请求生成本地 operationId 并记录阶段，但不伪装成后端幂等键。重试创建 Task 前先用返回的 Task code/id 判断是否已经创建；无法确认时要求用户人工决定，避免重复数据。

14. 构建、安装与首次配置

开发构建

./gradlew clean test buildPlugin verifyPlugin

产物位于 build/distributions/issue-link-push-idea-<version>.zip。开发运行优先让 Gradle 依赖本机 IDEA 路径，确保 API 与 IU-261.26222.65 一致。

从磁盘安装

  1. IDEA 打开 Settings → Plugins。
  2. 点击齿轮图标，选择 Install Plugin from Disk…。
  3. 选择构建出的 ZIP；不要手工解压。
  4. 按 IDEA 提示重启。
  5. 进入 Settings → Tools → Issue Link Push 完成账号配置与连接测试。

发布前检查

  • 单元测试全部通过。
  • Plugin Verifier 对 D:\softFile\idea-2026.1.4.win 无兼容性错误。
  • 新建隔离 IDEA 配置目录进行安装、升级和卸载验证。
  • 用测试 DevOps 数据完成 5 类写操作的冒烟测试。
  • 检查 ZIP 不包含凭据、真实响应样本或内部日志。

15. 插件升级、IDEA 升级与回滚

阶段 A：手工 ZIP 升级（首期）

  1. 保持插件 ID 不变，提高插件版本，例如 0.1.0 → 0.1.1。
  2. 构建并验证新 ZIP。
  3. 在 Plugins 页面再次执行 Install Plugin from Disk… 选择新 ZIP。
  4. 重启后插件状态和 PasswordSafe 凭据继续保留。

阶段 B：公司自定义插件仓库

在公司 HTTPS 服务放置 ZIP 和 updatePlugins.xml，用户只需在 IDEA 的 Custom Plugin Repositories 中添加一次地址。之后 IDEA 根据同一插件 ID、更高版本号和兼容范围提示更新。

<plugins>
  <plugin id="com.ctjsoft.devops.issue-link-push"
          url="https://plugins.company.example/issue-link-push-0.1.1.zip"
          version="0.1.1">
    <idea-version since-build="261.26222.65" until-build="261.*"/>
    <name>Issue Link Push</name>
  </plugin>
</plugins>

配置升级

  • 设置状态包含 schemaVersion；新增字段使用默认值，重命名/类型变化通过显式迁移处理。
  • PasswordSafe 的 service name 永久保持稳定，升级时不搬运或打印密码。
  • 项目映射格式变化时保留旧键的只读迁移，成功后再写新格式。

IDEA 自身升级

当前插件只声明 261.*。升级 IDEA 到 2026.2（262 分支）前，先为 262 构建新插件、运行 Verifier 和回归测试；不要通过手工修改 ZIP 中的 until-build 强行加载。

回滚

保留最近两个已验证 ZIP。若新版本异常，在 Plugins 中卸载/禁用新版本并安装旧 ZIP。若新版本已升级配置 schema，旧版仅在迁移设计声明向后兼容时回滚；否则先备份 IDEA 配置目录中的插件状态文件。DevOps/Git 已产生的远端写入不随插件回滚撤销。
