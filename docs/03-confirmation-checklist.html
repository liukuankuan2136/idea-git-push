当前确认状态

协议材料不再阻塞开发。普通任务列表固定使用 VS Code 的 groupId=6 / groupField=executeUser；不兼容网页端 groupId=1；忽略详情页保存产生的 /modify/task；增量 HAR 已满足真实 IIFE 样本要求。
确认项已全部收敛。C04 按推荐方案：登记用户实际选择的工时类型；C05 按现状方案：继续写入未展示章节的默认指导文案。C01–C03、C06–C12 按推荐方案实施。

建议直接确认的基线

#确认项推荐方案备选及影响
C01IDEA 兼容范围since 261.26222.65，until 261.*。保证当前本机，允许同分支修复版安装。锁死到 261.26222.65 更严格，但 IDEA 小升级后插件立即不可安装。
C02Git 主功能入口一个“关联 DevOps 工作项”入口，弹窗内切换仅提交/提交并推送/重写并推送。保留三个独立入口更像 VS Code，但菜单更长；底层仍可复用同一弹窗。
C03交互方式一个业务一个主弹窗，不再额外弹最终确认框；预览和警告常驻弹窗。对 amend 再弹一次确认更保守，但违背精简步骤目标。
C04
已确认		运维补录的工时类型最终方案：登记用户在弹窗中选择的工时类型，使 UI 与实际写入一致。不保留现版强制“代码编写”的不一致行为。
C05
已确认		简易任务模板最终方案：保持 VS Code 现状，未展示章节继续写入模板默认指导文案。不采用“只写实际填写章节”的精简方案。
C06push 失败后的运维流程继续登记工时，结果标为部分成功，并提供手动 push 指令；保持现版语义。push 失败即停止工时更“事务化”，但与当前业务习惯不同。
C07Task 创建后的工时失败保留 Task，支持原窗重试工时，不尝试自动删除任务。自动删除需要新增可靠删除接口与权限，风险更高。
C08升级方式首期本地 ZIP 覆盖安装；稳定后再接公司 HTTPS 自定义插件仓库。直接上 Marketplace 增加审核、公开性和维护成本。
C09升级提醒使用 IDEA 标准插件更新机制，不复刻启动时跳 GitHub Releases 的通知。保留自定义提醒会与 IDEA 更新提示重复。
C10DevOps 地址固定为 https://devops.ctjsoft.com，设置页只读展示。开放自定义地址会扩大安全与兼容范围，目前无明确需求。
C11日期时区全功能统一 Asia/Shanghai，修复凌晨可能登记到前一天的问题。机械复刻 UTC 行为会保留已知日期风险。
C12IDEA 插件版本线从 0.1.0 独立起步，变更日志注明对齐 VS Code 0.3.12 能力。使用 0.3.12-idea.1 更直观，但后续两端演进容易混淆。

开发开始前需要具备的材料

  • 确认上表 C01–C12，或指出需要调整的编号和目标行为。
  • 保留当前 VS Code 仓库作为业务基线；开发期间若 VS Code 功能继续变化，需要明确同步截止版本。
  • 已满足：loadtask-savedaywork.har 提供三份真实 IIFE 响应；开发前只需派生脱敏 fixture。
  • 准备可用于开发验证的 DevOps 测试账号/任务，避免在真实工作项上反复创建测试数据。
  • 确认 Git 测试远端，覆盖正常 push、首次 set-upstream 和故意 push 失败三类场景。
  • 若启用私有自动升级，准备一个可通过 HTTPS 访问的插件文件地址。
当前没有协议材料阻塞项。原始 HAR 只保留在本地取证目录并加入 .gitignore；自动化测试使用脱敏后的最小 fixture。
